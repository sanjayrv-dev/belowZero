# belowZero · Desktop bin, storage and vault specifications

Windows 11, local NTFS, x64 hardware acceptance first. ARM64 shares the layouts below and needs its own native build and device tests. File TRIM tells the storage stack which file bytes it may discard. Windows permits a later read to return the old bytes, zeros, ones or a mixture. Controller garbage collection and remapped NAND pages are outside the interface. Historical SSD sanitization research measured remnants by reading flash chips independently of the controller. ## Control codes and native layouts

`CTL_CODE = (device << 16) | (access << 14) | (function << 2) | method`. For the three controls below, the arguments are written as `(device, access, function, method)`. Generate definitions from a pinned Windows SDK. [Microsoft SDK header](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/winioctl.h)

- **`FSCTL_GET_RETRIEVAL_POINTERS`** = `0x00090073` from `(9,0,28,3)`. The proposal’s `0x000B0073` selects another device type.
- **`FSCTL_FILE_LEVEL_TRIM`** = `0x00098208` from `(9,2,130,0)`. The file handle needs write-data access. The proposal’s `0x00090230` is `FSCTL_GET_BOOT_AREA_INFO`.
- **`IOCTL_STORAGE_QUERY_PROPERTY`** = `0x002D1400` from `(0x2D,0,0x500,0)`. The SDK names the property result `DEVICE_TRIM_DESCRIPTOR`. `STORAGE_DEVICE_TRIM_DESCRIPTOR` in the brief refers to this type.

These declaration fragments use Windows' default packing, little-endian fields and synchronous I/O. For the two variable-length structures, the header and element occupy one contiguous buffer. Never marshal their native inline arrays as managed references. [DeviceIoControl](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-deviceiocontrol) · [TRIM input](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-file_level_trim) · [Extent output](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-retrieval_pointers_buffer) · [Device descriptor](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-device_trim_descriptor)

```csharp
[LibraryImport("kernel32.dll", SetLastError = true)]
internal static partial int DeviceIoControl(SafeFileHandle handle, uint code,
    nint input, uint inputBytes, nint output, uint outputBytes,
    out uint bytesReturned, nint overlapped);

[StructLayout(LayoutKind.Sequential)]
internal struct StartingVcnInput { public long StartingVcn; }
[StructLayout(LayoutKind.Sequential)]
internal struct RetrievalHeader { public uint ExtentCount; public long StartingVcn; }
[StructLayout(LayoutKind.Sequential)]
internal struct RetrievalExtent { public long NextVcn, Lcn; }
[StructLayout(LayoutKind.Sequential)]
internal struct TrimHeader { public uint Key, NumRanges; }
[StructLayout(LayoutKind.Sequential)]
internal struct TrimRange { public ulong Offset, Length; }
[StructLayout(LayoutKind.Sequential)]
internal struct TrimOutput { public uint NumRangesProcessed; }
[StructLayout(LayoutKind.Sequential)]
internal struct DeviceTrimDescriptor { public uint Version, Size; public byte TrimEnabled; }
```

1. **DeviceIoControl.** Native `BOOL` is four bytes. Pass a synchronous handle, zero `overlapped`, a real output count and buffers pinned or allocated through return. On zero result capture `Marshal.GetLastPInvokeError()` immediately. Check all lengths against actual bytes returned.
2. **Retrieval.** Input is 8 bytes. Output count starts at 0, four padding bytes precede the signed VCN at 8. First extent begins at 16, each pair occupies 16 bytes. Validate `returned >= 16` and `count <= (returned-16)/16`. Use the returned starting VCN, which Windows may round down. Each positive difference `NextVcn-currentVcn` is a length in clusters. Multiply by the volume’s bytes per cluster with checked arithmetic. LCN `-1` can denote a sparse hole or partial compression unit. Handle `ERROR_MORE_DATA` by parsing complete entries, continuing at the final next VCN and requiring forward progress. Bound output growth on insufficient buffer. Empty, unsupported and failed queries require distinct dispositions. [Retrieval control](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_retrieval_pointers)
3. **TRIM.** Key at 0 must be zero, positive count at 4, first range at 8. Offset and length are unsigned 64-bit **file bytes** at 0 and 8 within each range. Input length is checked `8+16*N` (24 for one). Output is one 4-byte count. Query system page size `P`. For range `[s,e)`, retain complete pages from `ceil(s/P)*P` to `floor(min(e,EOF)/P)*P`, using checked arithmetic. Zero eligible bytes means unsupported. For `P=4096` and a 4,097-byte file, show 4,096 eligible bytes and a one-byte uncovered tail before confirmation of best-effort TRIM plus ordinary unlink. Submit eligible bytes only through the caller-authorized file handle. Windows maps file offsets to storage. Require successful return, four output bytes and `NumRangesProcessed == NumRanges` before ordinary unlink. On partial result or malformed output preserve the directory entry, report potential content changes and stop. Report actual unlink outcome separately. A processed count describes API processing only. [Driver alignment and partial results](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/fsctl-file-level-trim)
4. **Descriptor.** Version at 0, Size at 4, native one-byte `BOOLEAN` at 8, three tail padding bytes, current size 12. Read the descriptor header first, bound its reported size, then require the returned buffer and version to cover the fields read. ABI tests should compare `Marshal.OffsetOf/SizeOf` to native `offsetof/sizeof` for each target.

A standard `STORAGE_PROPERTY_QUERY` has two 32-bit enums (property at 0, query type at 4), one inline byte at 8 and three padding bytes. Zero the full 12-byte input before setting its fields. An absent descriptor, a wrong version or a too-short result means unknown. [Storage query layout](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-storage_property_query)

## NTFS residence and the 800-byte assumption

The unnamed `$DATA` attribute may reside inside an MFT record. Record geometry, filenames and other attributes affect available space. NTFS documents the attribute form, with no universal 800-byte cutoff. Resident streams have no external extents. An empty file or inconclusive query also yields no usable external range. Exclude sparse, compressed and EFS streams, extra named data streams and multi-link targets from v1. Volume-wide BitLocker supports the file control. [MFT structure](https://learn.microsoft.com/en-us/windows/win32/devnotes/master-file-table) · [Attribute forms](https://learn.microsoft.com/en-us/windows/win32/devnotes/attribute-record-header)

**Scratch experiment.** Create a new 128-byte synthetic fixture on disposable NTFS and query VCN 0. Append real synthetic bytes with ordinary buffered writes until its length is at least two system pages and exceeds 4 KiB. Call `FlushFileBuffers` on the writing handle, check success, then repeat the extent query. Record file-record size, stream length and both results. External allocation demonstrates the new stream layout. Historical resident bytes remain unaccounted for. In the product, leave an ineligible source intact. Ordinary unlink removes a directory entry. Randomizing its name can generate journal entries carrying the old and new names. Windows exposes no file API to scrub historical `$FILE_NAME` copies. [MFT entry reuse](https://learn.microsoft.com/en-us/windows/win32/fileio/master-file-table) · [USN rename records](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/d2a2b53e-bf78-4ef3-90c7-21b918fab304)

## Device selection and USB bridges

Resolve the open file’s volume GUID. Query `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`, require a simple single-disk mapping, then query that disk using `STORAGE_PROPERTY_QUERY` with `PropertyStandardQuery=0`. Query `StorageDeviceProperty=0` for bus, `StorageDeviceSeekPenaltyProperty=7` for rotational evidence, and `StorageDeviceTrimProperty=8`. Treat a truncated or ambiguous response as unknown. Require local NTFS, a direct NVMe (17) or SATA (11) device, a valid `IncursSeekPenalty=FALSE` result and `TrimEnabled=TRUE`. If the model or topology contradicts those descriptors, classify it as unknown. Windows translates eligible ranges down the stack, potentially to SCSI UNMAP, ATA TRIM or NVMe Dataset Management Deallocate. The app cannot select or attest to the actual device command. SATA also serves rotating disks. USB (7), virtual, RAID, multi-device, missing capability or contradictory evidence selects a vault offer for future data. An enclosure can acknowledge a request without relaying it. Neither descriptor nor zero readback proves delivery. Moving plaintext into a vault leaves earlier storage exposure. [Volume mapping](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddvol/ni-ntddvol-ioctl_volume_get_volume_disk_extents) · [Property IDs](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ne-winioctl-storage_property_id) · [Bus types](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ne-winioctl-storage_bus_type)

1. **Create and identify.** On Windows 11 Pro, Enterprise or Education with a working BitLocker provider, create a fresh, dynamically expanding VHDX in an administrator-owned local directory. Suggested demo capacity is 1 GiB, subject to actual format/encryption success. Use device ID 3, Microsoft vendor GUID `EC984AEC-A0F9-47E9-901F-71415A66345B`, v2 creation parameters, access mask 0, aligned capacity, default block size, no parent or source. Close the creation handle, reopen that same file with v2 read/write parameters, attach with v1 reserved zero and `NO_DRIVE_LETTER=2`. Omit permanent lifetime. The session owner retains the attachment handle. Use `GetVirtualDiskPhysicalPath` and storage associations to initialize only this new disk as GPT. Create a basic-data partition, format that partition NTFS and identify its volume GUID. Recheck the disk/partition association before each write. [Disk type](https://learn.microsoft.com/en-us/windows/win32/api/virtdisk/ns-virtdisk-virtual_storage_type) · [Attach flags](https://learn.microsoft.com/en-us/windows/win32/api/virtdisk/ne-virtdisk-attach_virtual_disk_flag) · [Physical path](https://learn.microsoft.com/en-us/windows/win32/api/virtdisk/nf-virtdisk-getvirtualdiskphysicalpath)
2. **Mount privately.** Restrict both the new volume's root ACL and the empty NTFS mount folder. The Win32 operation is `SetVolumeMountPointW`. Both arguments require a trailing backslash. Verify the resulting mount with `GetVolumeNameForVolumeMountPointW`. The similarly named legacy WMI method is `root\CIMV2:Win32_Volume.AddMountPoint([in] string Directory) → uint32`. Use the Win32 function on Windows 11. Publish the user-accessible folder only after readiness. [Mount API](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setvolumemountpointw) · [AddMountPoint](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/vdswmi/addmountpoint-method-in-class-win32-volume)
3. **Prepare and protect.** Connect locally as administrator with WMI packet privacy to `root\cimv2\Security\MicrosoftVolumeEncryption`. Select `Win32_EncryptableVolume` by the new volume's `DeviceID`. On that fresh data volume, call `uint32 PrepareVolume(string DiscoveryVolumeType, uint32 ForceEncryptionType)` for native BitLocker and software encryption (1), then `uint32 ProtectKeyWithPassphrase([in,optional] string FriendlyName, [in] string Passphrase, [out] string VolumeKeyProtectorID)`. Generate 32 random bytes using the OS CSPRNG and encode losslessly into a policy-accepted passphrase. BitLocker generates its own encryption keys. The passphrase protects the persisted wrapped volume master key. The returned protector ID identifies the protector. [Provider](https://learn.microsoft.com/en-us/windows/win32/secprov/win32-encryptablevolume) · [PrepareVolume](https://learn.microsoft.com/en-us/windows/win32/secprov/preparevolume-win32-encryptablevolume) · [Passphrase protector](https://learn.microsoft.com/en-us/windows/win32/secprov/protectkeywithpassphrase-win32-encryptablevolume)
4. **Encrypt and qualify.** Call `uint32 Encrypt([in,optional] uint32 EncryptionMethod, [in,optional] uint32 EncryptionFlags)`. Values 6/7 select XTS-AES-128/256. Use an allowed software method with flags 0 for full-volume encryption. Flag 1 selects used-space-only encryption and is a separate performance experiment on a fresh image. The method normally starts asynchronous work. Check transport and method return codes independently. Require live `GetConversionStatus=FullyEncrypted(1)`, `GetProtectionStatus=ProtectionOn(1)`, expected method, exactly one expected protector of type 8, and auto-unlock disabled. Test the closing route on an empty disposable image under the actual build and policy before accepting sensitive data. Fail qualification on incompatible escrow/recovery rules. [Encrypt](https://learn.microsoft.com/en-us/windows/win32/secprov/encrypt-win32-encryptablevolume) · [Conversion status](https://learn.microsoft.com/en-us/windows/win32/secprov/getconversionstatus-win32-encryptablevolume) · [Protection status](https://learn.microsoft.com/en-us/windows/win32/secprov/getprotectionstatus-win32-encryptablevolume)
5. **Close and verify.** Quiesce writers, flush, then try `Lock(false)`. A busy volume remains open. The documented `FVE_E_RECOVERY_KEY_REQUIRED` (0x80310022) can block explicit lock for a passphrase-only volume. Allow a separately qualified clean-detach procedure only when exclusive volume quiescence can be acquired and maintained through removal of the verified mount and detachment. Reattach privately without a letter, match the image and volume identities, observe `GetLockStatus=1`, then detach and retire the owned backing file. Leave uncertain states for reconciliation. Clear application-owned credential buffers. The strongest observation is a locked image. WMI copies, paging, hibernation, memory dumps, application caches, exports and backups limit any claim of cryptographic erasure.
